# 湿地网页公开留言设计

状态：待确认的实施设计。这里只记录方案，线上提交功能尚未改动。

## 目标与范围

保留 https://acwangyan-cloud.github.io/shishui/ 的网址、绿色排版、25 张植物卡片、图片、宣传册、搜索和放大功能。替换现有的“预览后前往 GitHub”反馈流程。

同学不注册、不登录，也不用跳转 GitHub。填写后点击“提交留言”，后台确认保存成功后，留言立即出现在页面下方；刷新或换设备后仍能看到。留言不经过事前人工审核。使用当前已连接的 Sites 账户创建后台，不开通 Formspree，不购买付费服务。

## 页面与提交体验

- 保留观察/纠错类型、植物、公园、观察日期和内容；除内容外的具体信息均可不填。内容限制为 10—600 字。
- 不收集姓名、邮箱、电话、班级，不支持附件上传；不再提供参考链接输入框。
- 按钮改为“提交留言”，移除 GitHub 跳转、公开 issue 列表和“预览不等于提交”等旧说明。
- 表单旁仅保留简短提醒：“提交后将公开显示，请勿填写个人信息。”
- 下方“大家的留言”按提交时间倒序显示，首屏最多 20 条，可继续加载；显示内容、填写的观察信息和北京时间，不展示设备或网络标识。
- 留言按纯文本显示，不执行 HTML，不自动加载外部链接，不自动成为植物卡片结论。
- 提交中防止重复点击；保存失败保留输入。网络超时提示“暂未确认提交结果”，重试使用同一请求编号防止重复保存。
- 只有收到后台确认保存的响应，才显示“留言已公开”。列表加载失败和“尚无留言”分开显示，并提供重试。

## 后台与数据

创建专用的公开 Sites 服务和 D1 数据库，不迁移主网站。数据流为：原网页提交 → Sites 校验并保存 → 返回新留言 → 原网页展示。公共读取接口仅返回尚未撤下的留言字段，不返回管理信息或防刷记录。

接口分为公开读取、匿名提交和站主撤下留言三类。站主操作必须经过平台登录与服务端身份核对，不能依赖隐藏按钮，也不允许普通登录用户管理他人留言。管理身份仅绑定核实后的站主；无法确认身份时拒绝管理请求。

服务端独立检查字段类型、长度、植物选项和日期；使用参数化数据库语句。提交请求携带短时有效的表单授权信息，后台验证后才接受写入。浏览器访问来源仅允许原网页与后台自身；来源限制不作为唯一防刷措施。

加入频率限制、重复请求去重、请求大小限制及全站每日上限。共享校园网络采用宽松的网络级限额，不因为一个同学提交就阻止其他同学。防刷使用短期不可公开的网络摘要，不持久保存原始 IP；应用级防刷记录 24 小时内失效。托管平台自身可能保留正常访问日志，不承诺完全不可追踪。

管理端支持撤下及恢复留言，撤下后不再出现在公开列表。管理密钥及身份配置只存放于后台，不写进 GitHub 网页或公开源码。

## 验收与发布

1. 先验证后台是否支持当前账户的公开访问、匿名提交与数据持久化；如受账户权限限制，停止并说明，不静默更换服务。
2. 用明确标注的普通测试留言验证提交、刷新后读取及另一浏览器读取；测试完成后撤下测试留言。
3. 检查空列表、读取失败、提交失败、超时重试、重复点击及撤下流程，运行现有图鉴测试与新增留言测试。
4. 确认电脑和手机页面可正常使用；后台验证通过后再更新 GitHub 网页。
5. 若出现故障，保留现有图鉴可读性；不展示虚假的成功提示，不把仅保存在本机的内容冒充公共留言。

## 本次不做

不增加用户注册、点赞、回复、头像、附件、邮件通知、AI 审核或收费功能。公开留言无法保证完全没有垃圾内容，采用基础防刷和站主撤下功能管理。
